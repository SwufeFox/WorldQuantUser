# AlphaWinnow 评估（2026-11-28）

外部项目：`github.com/eslazarev/alphawinnow`，MIT，Rust CLI + 库，1.7 MB / 30 个 rs 文件。
定位是**本地公式化 alpha 挖掘引擎**：类型化表达式语法、确定性遗传编程、语义去重、
结构新颖性搜索、Rayon 并行、可选本地评估。明确不做 BRAIN 客户端、不做调度、不做提交。

## 它处在我们的哪一层

| 层 | 我们的现状 | AlphaWinnow |
|---|---|---|
| 候选生成 | LLM + 模板 + 人工设计 | 类型化 GP，确定性可复现 |
| 去重 | 骨架计数（结构） | 语义指纹（等价规则下同一身份） |
| 新颖性 | 无 | 有显式结构新颖度 |
| 反馈 | ledger 里 24k 条实测 alpha | ask/tell：按实测分数更新父代 |
| 平台交互 | 我们自己做（probe/daemon） | 明确不做，留给 adapter |

它把「生成 + 去重 + 按实测反馈选下一代」做成了闭环，正好是我们最薄的一段。

## 直接对得上我们痛点的三件事

1. **8 臂同骨架的问题**。我们现在的闸门数的是骨架（结构），它数的是语义身份——
   换窗口、换等价算子都会被折叠，能逼着我们用 8 个真不同的想法填满一批。
2. **冷启动重复烧**。它支持从已审计的历史表达式 warm-start 并排除已探索身份；
   我们 ledger 里有 24,141 个 alpha id、40,781 条台账，正好是它的输入形态。
3. **可复现**。确定性 GP + lineage，批次能重放出同一个候选集；我们现在做不到。

## 明确的限制

- 0.3.0 的 `compile` 用内置 parser，**不接受自定义 catalog**；内置算子覆盖
  `rank/zscore/winsorize/group_rank/group_count` 和 `ts_*` 一族（mean/delta/corr/
  cov/decay_linear/delay/ema/kurt/mad/max/median/min/rank/skew/std_dev/sum/var/wma/zscore），
  但**没有** `group_mean/group_zscore/group_neutralize/group_backfill`、`if_else`、
  `trade_when`、`vec_avg`、`signed_power`、`bucket`、`ts_argmax`。要覆盖我们常用写法得加映射层。
- 它不给任何收益承诺：文档里写明 structural score ≠ Sharpe，measured outcome 由调用方提供。
- pre-1.0，公开错误变体仍在加；要用就得锁版本。
- 需要 Rust 1.92+ 工具链；VPS 只有 2 核，编译要几分钟。

## 建议

不做整体替换。两条路：

**A. 只借思想**：把「语义身份」写进我们的闸门，用它替代现在的骨架计数；warm-start 用
ledger 自己实现（我们已有 40k 条台账，只差一个身份函数）。

**B. 做一次 spike**：本机编出二进制，导出单区（HKG/TOP500）的字段与算子 catalog，
生成 1,000 条候选，只比较两件事——合法率、与我们现有批次的语义重合率。不烧配额。
如果语义去重确实比骨架计数强，再考虑接 ask/tell。

倾向先做 B：它给出的是可比较的数字，而不是又一次「看起来不错」。

## 静态读代码后：值得抄的五件事

只看源码，不编译。以下都是可以在 Python 里重写的规则，不依赖 Rust 运行时。

### 1. 语义指纹：交换律排序 + 根尺度归一

`canonical.rs` 对标记为 commutative 的算子把参数排序后拼接，标量统一格式（`0` 不写成 `0.0`）。
`analysis.rs` 的 `semantic_root_normal_form` 再做两件事：根部的乘除把正标量因子剥掉
（`2*rank(x)` 与 `rank(x)` 同身份），负标量只保留符号差异；根部的重复加数折叠。

对我们的直接价值：现在 `2*rank(x)`、`0.5*rank(x)` 与 `rank(x)` 会被当成三条不同表达式，
实际是同一个身份。按这条规则折叠，8 个槽位能省出真不同的想法。`-rank(x)` 与 `rank(x)`
仍然分开，方向不同就是不同信号。

### 2. 结构描述符 + 固定权重距离

`novelty.rs` 用九个分量算 0–1 距离：算子 shingle 组 0.24、算子直方图 0.14、有序路径 0.16、
字段 0.08、字段家族 0.10、窗口分桶 0.08、分组 0.05、结构标志（非线性/条件）0.10、血缘 0.05。
每个分量都是 Jaccard 或直方图差，可解释、可审计。

我们的「同骨架」判据是二值的（相等/不等），它是连续的。换成阈值判定后，同一批里能说
「这八条两两距离都在 0.3 以上」，而不是「骨架标签不同」这种弱保证。

### 3. 保守的可证伪拒绝

`RejectionReason` 只有两项：`provably_zero`、`provably_constant`——都是结构上可证的，
不是启发式猜测。我们现在靠跑完回测发现全零或常量，等于用配额买一个本可以静态算出的结论。

### 4. 字段足迹分配

`field_diversity.rs` 把批次选择从「按分数截断」改成「按字段覆盖分配」，而且落选的不丢弃，
标注 deferred 留给后续批次。它自己写明：这只是分配启发式，不是语义去重，同一字段上的不同
机制仍然都算合法候选。这条正好补我们「8 条全挤在同一个数据集」的毛病。

### 5. 身份策略要版本化

`identity_reduction.rs` 有一段很硬的告诫：任何等价规则的改动都要给 dedup 策略打版本，
并且对历史表达式和新表达式用同一套规则重算，否则新旧身份不可比。我们改骨架归一化时
没做这件事，跨批次比较其实一直有隐性误差。

## 不抄的部分

GP 搜索本体（我们靠假设驱动 + LLM 出想法，不需要它那套变异/交叉）、Rust 工程结构、
catalog 的 generation_weight 体系。这三样要么重复造轮子，要么会把研究变成纯搜索。

## 工作量估计

前三条合计约 200–300 行 Python：规范化 + 指纹可独立成模块，描述符与距离在它之上，
拒绝规则只需一个恒等式化简器。第四条是选择启发式，第五条是纪律而非代码。

## 更正两处

1. **语义指纹不折叠窗口**。`canonical` 把参数原样渲染，窗口是参数，所以
   `ts_mean(close,5)` 与 `ts_mean(close,20)` 身份不同。窗口只是 `novelty` 里的
   `window_buckets` 距离分量，不是身份规则。前文那句「换窗口会被折叠」是错的。
2. **内置目录包含 `if_else`**。它出现在 `numeric.rs` 的条件求值与测试里；
   前文说「没有 if_else」不准确。缺的是 `group_mean/group_neutralize` 这类分组构造，
   不是条件算子。

## 上一次评估漏掉的层

上一版按「Python 能移植什么」筛了一遍，得到的是零件。真正有价值的是**研究策略本身被
写成对象**这件事。对应到源码：

| 构造 | 源码里的形态 | 它解决什么 |
|---|---|---|
| Ask/Tell | `measured_search.rs` 的 ask→proposal、tell→score snapshot | 生成与评价解耦，评价可以是黑的 |
| Evaluator Context | tell 要求「同一 evaluator + reference pool」的完整快照 | 防止把不同池/不同口径的分数放在一起比较 |
| Screened Feedback | `feedback.rs` 的 guided candidate：未测与已证伪分开 | 候选落选不等于被证伪 |
| Exploration Budget | `exploration_every`：每第 N 个变异强制新探索；=1 关闭父代利用 | 保留探索未知机制的能力，不靠自觉 |
| Parent Selection | `MeasuredParentSelection` 显式枚举 | 把「继续深挖谁」变成可替换对象 |
| Uniform Control | `LatestBatchUniformV1`：score-blind 保留，作为同批次对照 | 能回答「这套策略到底有没有用」 |
| Lineage | 候选带父代边，可回溯 | 追有效 alpha 的产生路径 |
| Reference Pool | 评价条件作为一等字段随分数存 | 让「同一口径」可判定而不是靠记忆 |

我们现在的对应物大多是隐式的：策略藏在 Agent 的推理里，评价口径散在台账的不同时期，
「继续深挖谁」是一句话判断，没有对照组。

## 范式差别

我们的循环是：读台账 → 想假设 → 写表达式 → 回测 → 记结果。策略每次重写在脑子里。

AlphaWinnow 的循环是：持久状态 → 生成策略 → 筛选策略 → 外部评价 → 状态更新。策略是
参数和数据，于是可以被冻结、替换、对照。

这带来一个我们现在做不到的能力：**单变量归因**。

- 冻结生成器，只换筛选器：筛选器有没有贡献？
- 冻结筛选器，只换父代选择：父代选择有没有贡献？
- 固定预算，开关历史反馈：反馈是否真的提高了效率？

这三问我们现在一个都答不了，因为每次实验同时改了三四个东西。

## 三个不需要 Rust 也不需要 GP 的实验

1. **对照组**：同一批 8 条，用「按实测分数选下一轮父代」与「盲选保留」各跑 20 批，
   比每千臂的 PASS 产出。这是 `LatestBatchUniformV1` 的移植，成本是记一个标记位。
2. **探索配额**：`exploration_every=4`，即每 4 条强制 1 条来自新机制（不同数据集/不同
   构造式），其余仍是同题变体。比「全变体」与「全探索」两条基线。
3. **评价口径隔离**：给台账每条记录补三件事——universe、训练窗口、检查版本——只允许
   同口径内比较。这条最便宜，也最能暴露我们过去「拿不同池的 Sharpe 比大小」的错误。

## 对「奥斯曼计划」的意义

如果长期目标是「能学习怎样生产因子的机器」，那零件优化（去重、静态拒）是必要的但不够：
它们让机器更省，不让它更会学。策略显式化才让它可学——有对照组、有归因、有可替换的策略。

短期代价要说清：这些字段不会立刻多出 alpha，前期只产出「我们的策略有没有用」的结论。
但那正是现在缺的那块。
